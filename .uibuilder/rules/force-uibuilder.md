# AR 实景界面强制规则

本规则约束当前项目中的 AR 实景界面设计任务。执行任何构思、画布写入或代码实现前，必须先读取 `.uibuilder/skills/uibuilder/SKILL.md`，再按 Skill 的路由读取与任务相关的参考文件。

## 触发范围

以下任务自动触发本规则：

- 创建、扩展、编辑、更新或还原 AR 实景界面。
- 创建全域监控、AR 实景监控、报警监控、报警分析或统计报表界面。
- 设计高点、轮巡、预置点、地图配置、画面范围、相机通道、回放、目标追踪、快照、录制、资源标签或点位事件流程。
- 调整黄色、青色、红色主题，沉浸、均衡、易读视效模式，或 1920/1280 响应式布局。
- 通过 Pixso MCP 读取、生成或修改上述业务的画布内容。

普通网站、移动活动页和与 AR 实景业务无关的自由视觉设计不触发本规则。

## 强制启动顺序

1. 完整读取 `.uibuilder/skills/uibuilder/SKILL.md`。
2. 根据需求只读取 Skill 指向的相关 `references/` 文件，不默认加载全部资料。
3. 通过 Pixso MCP 确认当前打开的是目标设计文件，并读取活动页面、选择状态、组件、变量和样式。
4. 定位与需求最接近的现有业务 Frame，先理解其结构、状态和交互，再开始设计。
5. 若 Pixso MCP 未连接或目标文件不正确，停止画布写入并说明阻塞，不得声称已经完成设计。

## 画布硬约束

- “AR实景设计规范11”Pixso 文件是当前 AR 业务的设计事实源；本地文档用于快速路由，冲突时以当前 Pixso 内容为准。
- 必须复用 Pixso 中已有的真实组件或组件集实例，不得凭名称手绘近似组件。
- 必须使用组件已有的 Variant、变量和共享样式；已有 Token 不得改为硬编码值。
- 不得拆分、扁平化或破坏组件实例，不得随意修改组件内部结构、状态命名和图层关系。
- 必须保持“真实场景层—业务信息层—交互操作层”的界面层级，避免 UI 大面积遮挡视频主体、人员、设备或环境信息。
- 必须根据目标尺寸使用 1920 或 1280 的对应布局与组件状态，不得只对整页进行等比缩放。
- 必须保留业务需要的正常、悬停、按下、聚焦、选中、禁用、加载、空数据、失败和报警状态；只制作需求实际涉及的状态。
- 不得编造设备、人员、点位、报警、时间、统计数据、业务规则或分析结论。缺失内容使用组件默认值或明确占位符。
- 用户未要求时，不新增无业务依据的面板、卡片、图表、操作入口、装饰或动效。

## Pixso 写入要求

1. 先读取参考 Frame 和目标组件，再执行创建或修改。
2. 写入组件实例时，先解析真实组件 GUID 和 Variant，不直接使用未经解析的资源 ID。
3. 编辑现有界面时尽量保持原节点和实例关系，只修改任务要求的内容。
4. 视觉值优先绑定当前文件变量；共享阴影、渐变等效果优先使用当前文件样式。
5. 涉及报警时保留报警语义，不把主题强调色与报警色混为一类。

## 完成标准

交付前必须完成以下检查：

- 所有新增可见 UI 均有现有组件、变量、样式或明确设计依据。
- 页面尺寸、面板位置、层级、间距、滚动和多语言截断符合对应参考。
- 无重叠、裁切、异常空白、字体回退、错误颜色或不一致尺寸。
- 关键业务状态和异常状态完整，没有只做理想正常状态。
- 使用 Pixso 截图检查最终画布；发现问题必须修正后再交付。
- 最终说明参考 Frame、目标分辨率、主题、视效模式、复用组件、覆盖状态和未解决的组件缺口。
