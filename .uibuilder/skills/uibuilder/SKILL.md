# Pixso AR 实景页面构建器

## 权威来源

Pixso“AR实景设计规范11”是设计事实源。静态文档负责路由和约束；组件、Variant、变量、样式与最新画布状态必须通过 Pixso MCP 核实。

开始任务先读取 [`references/index.md`](references/index.md)，再按任务类型读取对应页面、组件和工作流文档。

## 核心原则

1. AR 统一属于 HikCentral Professional 桌面客户端，不区分 B/C 端。
2. 先找最接近的规范 Frame，再复用真实组件实例；不得凭名称重画或自由拼造已有控件。
3. 主题与视效是页面级全局变量模式。不得逐组件硬编码颜色、透明度、阴影或描边。
4. 页面按“实景层—业务信息层—交互操作层”组织，避免遮挡关键视频内容。
5. 默认同时交付 1920 与 1280 两个独立 Frame；保持业务和操作一致，按规范分别适配，不得整体缩放。
6. 不编造设备、人员、报警、点位、时间、统计数据或业务结论。
7. 编辑已有页面只做任务所需的最小改动，保留实例、变量绑定、层级和业务关系。

## 必须工作流

1. 用 `fetch_context` 确认文件、页面、选区、变量与样式。
2. 读取 [`references/pixso-source-map.md`](references/pixso-source-map.md) 和对应 [`references/pages/`](references/pages/index.md) 页面规范，定位参考 Frame。
3. 先用 `read_components` 找候选组件，再用 `query_nodes` 获取实际 GUID、属性和 Variant；参照 [`references/components/index.md`](references/components/index.md) 核对用法与状态。
4. 在写入前完成页面结构、组件映射、主题/视效、状态及 1920/1280 适配方案。
5. 复制或继承最接近的规范 Frame，使用真实组件实例和现有变量写入两张适配稿。
6. 按组件自身能力覆盖任务所需的默认、悬停、按下、选中、禁用、加载、空数据、失败和报警状态。
7. 分别截图检查两个尺寸；修复遮挡、裁切、溢出、变量解绑、错误变体和功能不一致。
8. 交付时说明参考 Frame、组件映射、变量模式、尺寸差异、状态覆盖及组件缺口。

## 组件硬约束

- 已有组件必须使用真实实例；禁止用基础图层、HTML/CSS、截图或近似图标替代。
- 只允许切换已有 Variant/属性、修改暴露的文本或媒体槽位、调整实例外部布局和支持的尺寸。
- 禁止 detach、扁平化、增删或重排组件内部图层，也不得覆盖组件内部样式和自动布局。
- 找不到组件时继续查组件索引和 Pixso 节点；仍不存在则记录组件缺口，不得冒充规范组件。
- 只有用户明确要求并同意进入候选组件库后，才可单独设计新组件。

## 退化策略

Pixso MCP 不可用时，不声称已完成画布写入。仅输出待执行的页面结构、组件映射、状态、适配方案与缺口，等待连接恢复。
